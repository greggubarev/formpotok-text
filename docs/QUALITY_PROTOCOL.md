# Протокол проверки распознавания

Статус: диагностический контур готов; правила выбора кандидата ниже пока не закрыты. Наличие отчёта или 30 файлов в нём не означает независимую проверку качества.

## Набор документов

1. Для каждого документа сохраняются хеш исходного файла и версия проверенного текста. Группу исходного документа/шаблона можно назначить вручную: пересканированные страницы, экспорт того же PDF и варианты одной формы должны оставаться в одном разделе. Без группы старые записи остаются разделёнными по байтовому хешу и используются только для диагностики. Автоматического поиска похожих документов пока нет.
2. Перед сравнением создаётся неизменяемый снимок списка групп, версий эталонов и их хешей. Конечный контрольный набор не используется для подбора настроек. Изменение эталона создаёт новую версию набора и требует нового сравнения всех кандидатов.
3. Отмечаются типы страниц: скан, фотография, PDF с текстовым слоем, много колонок, таблицы, низкое качество. Проверяются разные источники и шаблоны, а не только число файлов.
4. Для замороженного набора запускается проверка похожих эталонов между разделами. Она обнаруживает часть повторов, но не заменяет ручную проверку происхождения документов и шаблонов.
5. Эталонные тексты выборочно сверяются с изображениями вторым проверяющим. Текст, исправленный только по подсказке текущего распознавания, не считается независимым подтверждением.

## Метрики

- Основная пара: CER и WER для полного текста документа. Политика `nfc-lower-invariant-collapse-whitespace-runes-v1` применяет NFC, строчные буквы и единичные пробелы; `ё` и пунктуация не удаляются. CER считает Unicode-символы, не UTF-16 единицы. Версия политики записывается в отчёт.
- Пустой ответ, ошибка и отсутствующий результат считаются отдельно. Неполный кандидат не получает агрегированный CER/WER. Проверяются худшие документы и грубые регрессии, а не только среднее.
- Сравнение кандидатов проводится попарно на одних группах. Разница должна сохраняться по типам документов и после оценки неопределённости; единичный удачный пример не является основанием для замены.

## Время и память

Кандидаты запускаются на одной Windows-машине с одинаковыми ограничениями. Холодный старт отделяется от прогретого запуска; время измеряется от подачи файла до готового текста. Память должна означать пик всего дерева процессов, а не только оболочки. Повторные запуски и конфигурация машины фиксируются вместе с версией кандидата. Отсутствующее измерение остаётся `null` и не трактуется как нулевой расход.

## Gate для выбора кандидата

- Не менее 30 независимых групп в замороженном контрольном разделе, без пересечения с разработочным разделом по документу и шаблону.
- Полный результат на каждом контрольном документе; отдельная проверка ошибок и худших случаев.
- Улучшение CER/WER на той же выборке без новых грубых регрессий. Задержка, память и размер поставки укладываются в заранее заданные бюджеты.
- Воспроизводимый отчёт: хеши набора и кандидата, конфигурация запуска, версия политики оценки и протокол измерения ресурсов.

До закрытия всех пунктов отчёты лаборатории используются только для диагностики.
