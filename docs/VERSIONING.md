# Версии продукта

`VERSION` в корне репозитория служит единственным источником версии приложения. Формат: `MAJOR.MINOR.PATCH`, для кандидатов `MAJOR.MINOR.PATCH-preview.N` или `MAJOR.MINOR.PATCH-rc.N`, где `N` начинается с 1 и увеличивается без повторов. Это подмножество [SemVer 2.0.0](https://semver.org/): предварительная версия ниже соответствующей стабильной. Метаданные `+...` в `VERSION` не пишем; commit хранится отдельно в манифесте пакета и .NET Product Version.

Пока продукт до `1.0.0`, номер `0.MINOR.PATCH` описывает пользовательский выпуск: `MINOR` обозначает новый набор возможностей или несовместимое изменение, `PATCH` обозначает совместимое исправление. После `1.0.0` несовместимое изменение данных, команд или форматов повышает `MAJOR`, совместимая функция повышает `MINOR`, а исправление без изменения контракта повышает `PATCH`. Даже в `0.x` изменение формата рабочей папки требует миграции или явного пути отката, а не потери старых документов. Смена OCR-модели без изменения формата может быть `PATCH`, но проходит отдельные quality-gates и описывается в заметках выпуска.

Кандидаты к одному базовому выпуску идут `preview.1`, `preview.2`, …, затем при необходимости `rc.1`, `rc.2`, … и стабильная версия без суффикса. Номер не переиспользуется для другого набора байтов. После публикации исправление получает новую версию; тег и файлы старого выпуска не заменяются. Исторические preview до принятия этой политики остаются без обратного переименования или создания фиктивных тегов.

Платформа не входит в версию: `win-x64` находится в имени ZIP/установщика и манифесте; будущая macOS-сборка той же версии получит свой RID. `Directory.Build.props` передаёт `VERSION` в .NET. Windows File Version содержит числовой `MAJOR.MINOR.PATCH.0`, а Product Version полную строку с суффиксом и commit. Установщик показывает ту же продуктовую версию.

Перед публикацией проверяются точные байты ZIP и установщика, их хеши и release-gates. Затем создаётся аннотированный тег `v<VERSION>` на commit из манифеста, `scripts/check-version.ps1 -RequireTag` подтверждает его. В GitHub предварительный выпуск помечается как prerelease. Публикация содержит краткие изменения, миграции, проверенные платформы, известные ограничения и SHA-256 файлов. Собранный кандидат без этих шагов не является опубликованным выпуском.

Отдельный снимок только исходного кода может иметь тег `source-YYYY-MM-DD`. Он не является версией приложения, не содержит ZIP или установщика и не заменяет проверки бинарного выпуска выше. В заметках такого снимка это указывается явно.
