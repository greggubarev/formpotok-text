# Локальная диагностическая лаборатория

Скрипты создают синтетические русскоязычные страницы с заранее известным текстом и прогоняют их через тот же офлайн-комплект, который входит в Windows-пакет. Исходники и результаты создаются во временном каталоге, не входят в репозиторий. Нужны Windows, .NET SDK 10, Python 3.10 с Pillow и собранный переносимый пакет с моделями.

```powershell
$package = 'C:\path\to\FormPotok.Text-win-x64-v0.1.0-preview.6'
$corpus = Join-Path $env:TEMP 'formpotok-russian-corpus'
$results = Join-Path $env:TEMP 'formpotok-russian-results'
py -3.10 tools/quality-lab/generate_russian_corpus.py $corpus
dotnet build tools/LocalTextSmoke/LocalTextSmoke.csproj -c Release
./tools/quality-lab/run_synthetic_corpus.ps1 -Package $package -Corpus $corpus -Results $results
```

Для страниц со сложной вёрсткой замените генератор на `generate_layout_corpus.py` и используйте отдельные каталоги. Каждый запуск требует нового каталога результатов. Сводка `corpus-summary.json` содержит хеши источников и пакета, метрики и ошибки, но не текст документов. Если хотя бы один случай не завершён, агрегированные CER/WER остаются пустыми. Подробные локальные выходы содержат распознанный текст и не предназначены для публикации без проверки.

Для числовых таблиц есть отдельный воспроизводимый набор: 4, 12 и 24 строки, для каждого размера чистый вариант, поворот 1,6°, мягкое размытие, снижение разрешения и их сочетание (15 страниц). `corpus.reference.json` содержит полный эталон: заголовок, имена колонок, каждую строку и итоговую сумму. Все страницы относятся к одной `sourceGroup`: у них общий шаблон и пересекающиеся строки, поэтому это не независимые документы. Изображения и хеши повторяются при повторном запуске в той же среде; при смене версии Pillow или системных шрифтов байты могут отличаться, поэтому манифест всегда создаётся вместе с изображениями.

```powershell
$corpus = Join-Path $env:TEMP 'formpotok-numeric-tables'
$results = Join-Path $env:TEMP 'formpotok-numeric-results'
py -3.10 -m unittest discover -s tools/quality-lab -p 'test_*.py' -v
py -3.10 tools/quality-lab/generate_numeric_table_corpus.py $corpus
./tools/quality-lab/run_synthetic_corpus.ps1 -Package $package -Corpus $corpus -Results $results
```

Для повторного OCR-прогона задайте новый каталог `$results`. Тесты генератора и метрики не требуют пакета или моделей, только Python 3.10 и Pillow. Runner вызывает Python 3.10 для числовых случаев.

Для числового корпуса в манифесте также заранее объявлены все четыре ячейки каждой строки данных (`numericTable.rows`). Дополнительные `exactCellRate` и `exactRowRate` в `corpus-summary.json` показывают долю полностью совпавших ячеек и строк; в `results` остаются только счётчики. Заголовок, названия колонок и итоговая сумма в эти две метрики не входят; они остаются в полном текстовом эталоне для CER/WER и проверки маркера. Сопоставление выполняется по токенам полного текста страницы: Unicode NFKC, регистр и количество пробелов нормализуются, но знаки, разделитель дробной части и цифры должны совпадать точно. Строка считается верной, только если все четыре ячейки выровнены подряд. Метрика не оценивает геометрию таблицы и может ошибаться при перестановке одинаковых токенов. Для ненумерических корпусов поля равны `null`; при ошибке любого случая агрегаты, как и CER/WER, равны `null`. Локальный `reviewed.txt` содержит текст и не должен публиковаться без проверки.

Для проверки изменений в исходном sidecar без пересборки всего пакета укажите `-SourceSidecarScript tools/ocr-sidecar/main.py -SourcePython <путь к локальному Python с установленными зависимостями> -ModelCache <локальный каталог моделей>`. Скрипт копирует исходники sidecar в каталог результатов до запуска и записывает их хеши, поэтому весь прогон использует одну версию. Это лабораторный режим, не готовая пользовательская сборка.

Обе выборки синтетические и диагностические. Шесть вариантов одного шаблона не являются шестью независимыми группами. Измеренные на них числа нельзя переносить на пользовательские документы или использовать как gate замены модели.

Для эталонов, сохранённых из приложения, сначала назначьте группы и создайте снимок по [инструкции разработчика](../../docs/DEVELOPMENT.md). Затем проверьте пересечения между разделами:

```powershell
dotnet run --project tools/LocalQualityRunner/LocalQualityRunner.csproj -- audit $lab $snapshot (Join-Path $env:TEMP 'formpotok-leakage-audit.json')
```

Проверка ищет совпадающие шаблоны и похожий текст, подменяя в сравнении последовательности цифр. Это эвристика: отсутствие предупреждений не доказывает независимость документов. В отчёт попадают только хеши и оценки сходства, а не исходные тексты.

## Изолированный RapidOCR

Этот кандидат не входит в приложение и не меняет установленный OCR. Для него нужен отдельный Python 3.10 venv с `rapidocr==3.10.0`, `onnxruntime==1.23.2` и `pypdfium2==5.14.0`. Модели один раз загружаются из источника, указанного в `rapidocr-models.lock.json`, в локальный каталог; перед каждым запуском адаптер проверяет версии и SHA-256 файлов. Путь к моделям задаётся явно. В ходе прогона пользовательские файлы никуда не отправляются.

```powershell
$python = 'C:\path\to\rapidocr-venv\Scripts\python.exe'
$models = 'C:\path\to\rapidocr-models'
$corpus = 'C:\path\to\russian-corpus'
& $python tools/quality-lab/compare_rapidocr.py --corpus $corpus --model-root $models --output (Join-Path $env:TEMP 'rapidocr-comparison.json')
& $python tools/quality-lab/rapidocr_candidate.py --model-root $models --language cyrillic 'C:\path\to\scan.png'
```

Адаптер пишет распознанный UTF-8 текст в stdout, диагностику в stderr. Отчёт сравнения содержит метрики и хеши без текста документов. Для одного кандидата на локальных проверенных эталонах используйте внешний runner из `tools/LocalQualityRunner` с абсолютными путями к Python, адаптеру и моделям. Синтетический корпус годится для отладки, но не для решения о замене основного движка. План и результаты других кандидатов находятся в [плане экспериментов](../../docs/OCR_CANDIDATE_EXPERIMENTS.md).

После прогона текущего пакета на том же корпусе `summarize_rapidocr_ab.py --baseline <corpus-summary.json> --candidate <rapidocr-comparison.json> --output <ab-summary.json>` проверит, что SHA-256 манифеста, набор файлов и длины нормализованных эталонов совпадают. Если отчёты относятся к разным корпусам или один прогон неполный, сводка завершится ошибкой.

## Поворот, сложная вёрстка и структура таблиц

`generate_rotation_corpus.py` создаёт десять вариантов двух чистых страниц из русского корпуса. `render_rotation_outputs.py` возвращает обработанные OCRmyPDF PDF в изображения с теми же текстовыми эталонами. Затем оба каталога проверяются обычным `run_synthetic_corpus.ps1` на одном Windows-пакете. OCRmyPDF, Tesseract и Ghostscript используются только в отдельном лабораторном окружении; в поставку приложения они не входят. Для повёрнутых портретных страниц можно отдельно прогнать исходный sidecar через `-SourceSidecarScript` и `-SourcePython`, не пересобирая пакет.

`generate_layout_corpus.py` создаёт 12 страниц трёх типов. Текстовый экспорт Docling, запущенного с локальными моделями и без сети, оценивает `score_docling_layout.py --corpus <corpus> --outputs <docling-text-dir> --output <report.json>`. Отчёт содержит метрики и хеш корпуса, не текст страниц. Для A/B на тех же изображениях отдельно запускается основной runner.

`generate_numeric_table_corpus.py` создаёт 15 числовых сеток; `generate_structural_table_corpus.py` добавляет три варианта одной таблицы с пустыми и объединёнными ячейками. `run_table_v2_lab.py --corpus <corpus> --model-root <local-paddlex-official_models> --output <report.json> --files <comma-separated-names>` запускает Table Recognition v2 на CPU с локальными весами. В отчёте точные ячейки, строки и объединения; распознанный HTML не публикуется. Все эти наборы синтетические и не заменяют проверку на независимых документах.
